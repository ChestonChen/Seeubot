# Seeubot 项目实现历程

## 闭环 0 ｜ 先让屏幕上出现一个黑色胶囊，尺寸任意

1. 给app设置一个委托对象，然后把启动app的工作准备交给委托对象处理（类我们自定义实现）

2. 准备创建一个panel窗口（辅助面板，比如调色板，搜索框的东西）是window子类，我们默认window是一个窗口，window尺寸可以调整，但panel尺寸通常是写死的（附着在window内部一个一个面板）

为什么不用window ？`NSPanel`苹果专门为「辅助小面板」准备的窗口子类（普通窗口是 `NSWindow`）。它天生支持不抢焦点、不参与 `Cmd+Tab`，正好是悬浮挂件需要的

panel的属性设置为 不透明不抢焦点，不会因切走app窗口隐藏，缩放时尺寸不变不响应鼠标事件

用swiftui设置点击相应以及相应接受对象，及包装view塞给contentview，决定事件进来了怎么办

5. 设定各个类型组件的长宽圆角尺寸

6. 用swiftui设置一个黑块，然后把它用panel包起来，这样swiftui的ui就能在panel上显示了

**先有 SwiftUI 视图 → 用 NSHostingView 包成 AppKit 视图 → 再塞进 panel 的 contentView**

7. 实现启动函数：设置一个不抢焦点的app无文本，算一下屏幕类型是否有刘海，把swiftui视图盖在panel上

并规定尺寸，创建一个panel并把之前设定好的属性都初始化，把视图给panel上，强制在窗口最前面，并设定监听，屏幕参数变化触发回调，回调就是重新算尺寸重新上映

**启动完成时选屏幕 → 建视图 → 建面板 → 塞进去 → 摆到屏幕顶部 → 显示**

结果：屏幕上方出现一个黑色胶囊

## 闭环 1 ｜ 把闭环0的胶囊放到刘海下面，然后悬挂态

8. 设置全局所有组件颜色，panel包括了swiftui，里面又包括岛，岛是一个外壳，内部有各个组件（胶囊，长条，看板，panel 是"画框"（存在但透明），岛是"画的形状"（有颜色有阴影），药丸是岛收起时装的内容。 三者是「窗口 → 外壳 → 内容」的三层关系，岛的职责只有一件事：把当前状态下该显示的内容画出来

9. 设置等宽字体和圆角字体

**为什么需要等宽体** —— 界面上的数字每 3 秒刷新一次，如果数字宽度不一样，整行会左右抖动

10. 设计一个专门计算尺寸的类 measure方法并返回一个尺寸结构体

11. 定义一个swiftui的圆角画法

12. 把闭环0中的黑色胶囊重新定义尺寸，挂在刘海屏幕下

## 闭环 2 ｜ 鼠标放入热区展开，移出缩回

1. 创建一个界面状态仓库，记录屏幕几何和鼠标是否在热区，变化了通知对应回调

纯状态容器：存 `metrics` / `hover`，被改了就通知 SwiftUI 重画

app delegate是装配层：谁和谁连起来、什么时候连 —— 监听系统通知属于这里

1. 把swiftui根视图改成订阅仓库，并根据 `hover` 决定自己多宽、圆角多大、内容多大

3. 创建一个定时器，每0.1秒看鼠标是否在热区内（内部函数算坐标包含关系），用bool记录是否在内部

在热区就接收鼠标事件

结果，鼠标移动热区，有对应的展开态

```text
NSPanel（窗口）                      440×540  全透明，看不见
└─ contentView = FirstMouseHostingView  440×540  是 NSView，全透明，看不见
   └─ SwiftUI 画布（NotchRootView）      440×540  看不见
      └─ 岛（内容+修饰符的组合）          384×253  可见：渐变底+描边+投影
         └─ 内容（占位块 / 之后的看板）    300×220  可见：更黑
```

收起态那个也是岛

panel 是窗户，contentView 是窗框上的玻璃（透明），岛是贴在玻璃上的画，内容是画里画的东西

## 闭环 5 ｜ 从文件中真正算出token

1. 在数据采集器加一个判断是否working的时间45s

2. 添加会话的信息 1会话一个struct，进程和文件匹配，查找进程，策略模式下的不同agent配对

过程为：根据agent adapter集成去找他的会话文件路径（文件测），然后遍历进程，为每个进程找它的会话文件（拿着进程的 cwd 和它打开的文件，去文件表里反查它的会话文件），第三步进行配对每一个agent对应的会话文件，是以进程为主体去找文件，而不是以文件为主体去找进程

3. 在采集器中加了一个缓存，一个汇聚agent的变量

4. 添加采集器的函数：找文件目录，记录取文件的时间和字节数（用于判断是否用缓存，否则找到文件并解析），累计token，解析claude，codex的方法

Claude：增量累加 + 去重

逐行读 JSONL，只认 `type == "assistant"` 且带 `usage` 的行。每条 usage 是这一条消息花了多少，所以直接累加。

但一次回复会写多行、每行都带同一份 usage，所以要用 `message.id` 去重（见过就跳过），否则 token 会被放大几倍。

今日量：看每行自己的 `timestamp` 是不是今天。

Codex：累计值取最后 + 相减

逐行读，`total_token_usage` 是到目前一共花了多少（累计），不能相加。

- 总量 = 最后一条累计快照
- 今日量 = 最后一条累计 − 今天之前最后一条累计

5. 先写上支持的agent适配函数

6. 补全collect，先枚举+解析（上一步）→ 扫进程（闭环 6）→ 配对 → 汇总

## 闭环 6 ｜ 跑着 `claude` 或 `codex` 时，看板的 `LIVE SESSIONS` 出现条目

1. 写一个runcmd通用函数，*把它的输出当字符串返回。全项目只用它跑 `ps` 和 `lsof`*

2. *先用 `ps` 拿到所有进程、用 adapter 判断哪些是 AI 工具的；再用 `lsof` 问每个进程「你的工作目录是什么、你正打开着哪个 jsonl*

3. *把「进程」和「会话文件」配起来。策略两级：先看它正打开的文件（最准），不行再按工作目录推断*

4. 把闭环 5 里那两个**占位 adapter** 换成真实版：接上「怎么认进程」和「怎么配对」。换完之后，`collect()` 才第一次能配出活会话
